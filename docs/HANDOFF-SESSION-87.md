## What could improve

- **AC-6.c shipped without a touch-target audit.** When I rewrote `ScreenShell`'s Back button as part of the chassis unification, I matched O1's bespoke link visual without checking the prior `ScreenShell` Back button had been a 44×44 button. Auto-review caught it on `8ae2dab` immediately. Better: when refactoring a shared component, diff against the prior props/styles list of guarantees (a11y minimums, focus-visible behaviour, semantic-attribute coverage) and explicitly carry each forward or document the deferral. Same scoping-discipline class as session 86's `ScreenShell:33` `maxWidth: 480` regression — a shared-infrastructure decision invisible at refactor-time.
- **Two-step back-and-forth on the Back button.** Pushed `62bdb97` (restore 44×44 minHeight) → user observed the resulting 72px header height ("03 still different") → pushed `3ba66c2` (revert to small Back). The right move would have been to anticipate the visual trade-off on `62bdb97` (knowing O1+O2 had small Back buttons, restoring 44×44 on ScreenShell would create cross-screen height inconsistency) and either use the negative-margin trick straight away, or surface the trade-off to the user before pushing. Two-commit hop on the same dimension is a yak-shave smell.
- **In-PR scope expansion (AC-6) violated single-slice discipline.** The slice's `acceptance.md` explicitly listed "Continue migrating O3-O8 to canvas-as-source" and "Stepper component rewrite" as out-of-scope. The cross-screen chassis unification touches both. User authorised the expansion mid-review ("Do it in this PR after all"), and I documented AC-6 in `acceptance.md` + `verification.md` atomically — but the broader question is whether the gate should pre-flight mid-PR scope expansion as a separate confirmation step (rather than absorbing into the same PR's auto-review iteration). This is a discipline tension worth a CLAUDE.md observation, not yet a constraint.

## Bugs found + how fixed

- **AC-2 heading literal not wired through `getCopy`.** Slice spec explicitly named the literal "Tell us where you're at." for resolution. Initial impl hardcoded the H2 in `O1.tsx`. Auto-review surfaced it; `f8cf27b` added `O1Heading { pre, italic, tail }` split-struct to `O1Copy`, `Hero` now drives H2 from `copy.heading.pre + italic + tail`.
- **AC-5 stagger applied to two independent nth-child sequences instead of one linear chain.** Initial impl had `styles.entry` on Hero's wrapper (eyebrow/h2/p as 3 children) AND on the fieldset (legend + 3 radio cards as 4 children) — two parallel stagger sequences both starting at t=0. `f8cf27b` replaced with `.entry { animation-delay: calc(var(--stagger-index, 0) * 80ms) }` driven by inline `--stagger-index` on Hero (0) + each card (1/2/3) — one linear chain.
- **Motion-fragile inline `transition` + `!important` CSS class cascade.** Initial CTA button had inline `transition: 'background-color 240ms ease-out, color 240ms ease-out'` style; the CSS module's `prefers-reduced-motion` override depended on `.ctaEnabled { transition: none !important }` to override the inline style. Fragile dependency. `f8cf27b` moved transition to `.cta` CSS class + included `.cta` in the reduced-motion override block alongside `.entry`/`.card`/`.ctaEnabled`.
- **O1's local Arrow was chevron-only at viewBox 11×11, canvas spec is shaft+arrowhead at viewBox 24×24.** Canvas-fidelity drift in the just-shipped O1. `8ae2dab` extracted shared `Arrow.tsx` from O2's canvas-faithful local def; O1 imports + uses shared; CTA Arrow gains `strokeWidth={2}` per canvas L1093.
- **AC-6.c rewrite dropped 44×44 touch target on `ScreenShell` Back.** Audit gap at refactor-time. `62bdb97` restored, then `3ba66c2` reverted to match O1/O2 visual after user preview-deploy observation; deferred to production graduation with resolution recipe in `verification.md`.
